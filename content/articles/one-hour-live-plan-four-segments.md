**រឿងឧទាហរណ៍** (មិនមែនអតិថិជនពិត)

*ស៊េរី Live → Order*

ហាងខោអាវនារីមួយនៅភ្នំពេញ Live រៀងរាល់យប់ ២ ម៉ោង។ ម្ចាស់ហាងចាប់យកអាវណាមួយនៅជិតដៃ បង្ហាញម្ដងមួយៗ រហូតដល់អស់កម្លាំង។ Comment ចូលច្រើន តែពេលរាប់ Order មិនដល់ពាក់កណ្ដាលនៃអ្វីដែលគាត់រំពឹង។ បញ្ហាមិនមែនទំនិញទេ គឺ Live គ្មាន **យុទ្ធសាស្ត្រ Live** ច្បាស់ ថាបង្ហាញអ្វីមុន អ្វីក្រោយ និងបិទ Order ពេលណា។

## លេខមុនប្ដូរ

**ឧទាហរណ៍សម្រាប់បង្ហាញវិធីគណនា** (មិនមែនទិន្នន័យអតិថិជនពិត)។ Live មួយយប់ ២ ម៉ោង៖

- Boost Live $10 · Comment សួរទិញ ១២០ · Order បញ្ជាក់ ១២
- **Order ក្នុងមួយម៉ោង** = 12 ÷ 2 = **៦**
- **Cost per Order** = $10 ÷ 12 ≈ **$0.83**

ពេលពិនិត្យ Comment ឡើងវិញ គាត់ឃើញថា ភ្ញៀវច្រើនសួរ «ឈុតមុនតម្លៃប៉ុន្មាន?» តែម្ចាស់ហាងបានប្ដូរទៅអាវផ្សេងរួចហើយ។ ភ្ញៀវថ្មីដែលទើបចូល ក៏មិនដឹងថាកុម្ម៉ង់យ៉ាងណា។

## ផែនការ Live ១ ម៉ោង ៤ វគ្គ

គាត់កាត់ Live មកនៅ ១ ម៉ោង ហើយរៀបលំដាប់ទំនិញជាមុន៖

**នាទី ០–១០៖ បើក Live ដោយទំនិញលក់ដាច់ជាងគេ**
ប្រាប់ថាថ្ងៃនេះមានអ្វីខ្លះ និងរបៀបកុម្ម៉ង់ (លេខកូដ + ទំហំ)។ បង្ហាញឈុតដែលធ្លាប់លក់ដាច់មុនគេ ព្រោះវាទាញ Comment ដំបូងៗ ហើយធ្វើឲ្យ Live សកម្ម។

**នាទី ១០–២៥៖ ទំនិញសំខាន់ ២–៣ មុខ ដែលមានស្តុកគ្រប់**
ពាក់សាកគ្រប់ឈុត ប្រាប់ទំហំ កម្ពស់ និងទម្ងន់អ្នកពាក់។ ឈុតនីមួយៗមាន [លេខកូដទំនិញ](/knowledge/product-codes-for-live-orders/) ច្បាស់។

**នាទី ២៥–៤៥៖ ឈុតផ្គូផ្គង និងទំនិញបន្ថែម**
បង្ហាញអាវជាមួយខោ ឬកាបូបដែលពាក់ជាមួយគ្នា។ វគ្គនេះជួយឲ្យ Order នីមួយៗធំជាងមុន ដោយមិនបាច់ចាយ Boost បន្ថែម។

**នាទី ៤៥–៦០៖ ទំនិញនៅសល់តិច ហើយសរុប**
ប្រាប់តែស្តុកពិត ដូចជា «ពណ៌ខ្មៅ M នៅសល់ ៣ ឈុត»។ ចុងក្រោយ និយាយខ្លីៗថា Admin នឹងផ្ញើសារបញ្ជាក់ Order ក្នុង Messenger ហើយភ្ញៀវត្រូវឆ្លើយឈ្មោះ លេខទូរស័ព្ទ និងទីតាំង។
